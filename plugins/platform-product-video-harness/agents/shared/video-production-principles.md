# Video Production Principles

These principles apply to every product video generated by this plugin. The **compositor** must follow them when writing Remotion compositions. The **reviewer** must flag violations as blocking findings.

This file is the domain-specific counterpart of the SDLC harness's generic SOLID/DRY/YAGNI. None of these are language-best-practices; they are video-output rules that protect the brand and ensure outputs are postable.

## Brand tokens always — no hardcoded hex / fonts

Every color and font in a composition must come from `<ProductVideos>/brand/brand.json`:

```tsx
import { brand } from '../brand/brand.json';

// ✅ correct
<Text style={{ color: brand.colors.primary, fontFamily: brand.fonts.heading }}>
// ❌ wrong — reviewer flags as CRITICAL
<Text style={{ color: '#2563EB', fontFamily: 'Inter' }}>
```

Reviewer regex: any `#[0-9a-fA-F]{3,8}` literal in `compositions/*.tsx` outside `brand.json` itself → CRITICAL.

## Captions burned in for accessibility

Every voiceover line gets an on-screen caption via the `<CaptionStrip>` component, synced to the scene's frame range. No exceptions — short-form social-media video is consumed muted by default; captions are not optional.

Reviewer: scan `script.md` for voiceover lines; for each, confirm a `<CaptionStrip text="…">` appears in the composition with matching start/end frames. Missing caption → CRITICAL.

## Audio levels — social broadcast standard

- **Voiceover**: normalised to **-16 LUFS integrated** (Reels / YouTube target).
- **BGM bed**: ducked to **-28 LUFS integrated** (sits clearly under the voice).
- Tolerance: ±2 LU. Outside that → reviewer halts.

Verification command (run by the reviewer):
```bash
ffmpeg -i <output.mp4> -af loudnorm=print_format=summary -f null -
```

Look for `Input Integrated:` — must be within `-16 ± 2 LU` for the muxed track, or the voiceover stem if mixed separately.

## Hook in the first 3 seconds

Scene 1 must establish the product or problem within the first 3 seconds — this is non-negotiable for social-media retention. The scriptwriter enforces this template-side (every template's Scene 1 has a `target_duration` of 2-3s and a `purpose: hook` annotation). The reviewer flags violations: if Scene 1 in `script.md` runs longer than 3s, or doesn't include a visual showing the product, → CRITICAL.

## CTA before the final 5 seconds

The last scene of every video is reserved for the call to action (download / try / learn more / visit). Never trailing logo-only / empty endings.

Reviewer: read `script.md`; confirm the final scene's voiceover contains an action verb (download, try, get, visit, learn, sign up). Missing → CRITICAL.

## Compositions stay composable

Anything reusable across videos must live in `compositions/_components/`. Per-video compositions (`compositions/<slug>.tsx`) must stay declarative and short.

- Hard limit: per-video composition **> 150 lines** → compositor extracts to `_components/` before the next render.
- Reviewer flags any per-video composition over 150 lines as WARNING (not blocking, but visible).

## Duration discipline

Final MP4 duration must be within **±2 seconds** of the script's declared `target_duration`. The reviewer halts on overshoot:

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 <output.mp4>
```

If `|actual - target| > 2`, the workflow loops back to scriptwriter with the actual vs target.

## No raw HTML in compositions

Use Remotion primitives (`<AbsoluteFill>`, `<Sequence>`, `<Series>`, `<Img>`, `<Audio>`, `<Video>`) or components from `compositions/_components/`. Never `<div>` / `<img>` / `<button>` — Remotion's primitives know about its rendering model; raw HTML elements break in certain contexts (server-side render, audio sync).

Reviewer: grep `compositions/*.tsx` for raw HTML element tags → CRITICAL.

## Aspect-ratio safe zones

When designing scenes:

- **9:16 (vertical, 1080×1920)**: keep critical content within the central 1080×1350 — top and bottom 285px are often clipped by platform UI (Reels caption bar, profile icons).
- **1:1 (square, 1080×1080)**: full frame is safe.
- **16:9 (horizontal, 1920×1080)**: keep critical content within the central 1620×1080 — outer 150px each side may be cropped on some embeds.

The shared `<SafeArea>` component in `_components/` adapts to the active composition's dimensions via `useVideoConfig()` and applies the right padding per aspect ratio. Wrap every scene's content in `<SafeArea>`.

## Asset rules

- Source assets in `projects/<slug>/assets/` are read via Remotion's `staticFile('<slug>/<asset>')` after being copied to `public/<slug>/`.
- Maximum source asset size: **10MB** per file (enforced by `large-media-guard.sh`). Larger assets → compress (PNG → WebP, MP4 → re-encode at lower bitrate) before adding.
- No real customer data in assets (no actual user names / transaction IDs / phone numbers).

## Voice settings consistency

The narrator uses the same ElevenLabs `voice_settings` for every call within a video:

```json
{
  "stability": 0.5,
  "similarity_boost": 0.75,
  "style": 0.0,
  "use_speaker_boost": true
}
```

Stability 0.5 + similarity 0.75 produces consistent timbre across scenes without sounding monotone. The voice ID is pinned in `<ProductVideos>/.claude/context/platform-video-context.md`.

## Output naming

- `out/9-16.mp4` — Reels, TikTok, YouTube Shorts (1080×1920)
- `out/1-1.mp4` — Instagram Feed (1080×1080)
- `out/16-9.mp4` — YouTube long-form, LinkedIn (1920×1080)

No alternative names, no version suffixes in the filename (use git history or rename on copy-out if you need to keep variants).
