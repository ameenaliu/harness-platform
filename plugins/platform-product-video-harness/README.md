# platform-product-video-harness

**AI-Driven Product-Video Generation** — a Claude Code plugin that turns a one-paragraph brief + design assets + (optionally) a sample reference video into 3 social-media-ready MP4s (9:16 + 1:1 + 16:9) in one pipeline run. Uses ffmpeg for frame extraction, Claude vision for sample analysis, Remotion for composition, ElevenLabs for voiceover + ambient bed.

**Brand-agnostic.** The harness has no built-in brand — each project supplies its own brand kit (name / palette / logo / personas / tone), collected per-workspace at init into `<ProductVideos>/brand/brand.json`. The `name` is seeded from the workspace folder; everything else is a neutral starter you replace via the init flow or `/update-brand-kit`.

**GitHub-native.** Ships in the `harness-platform` marketplace on GitHub. The `ProductVideos` workspace is a local folder, optionally backed by a GitHub repo you supply.

**Runs on two tools.** Claude Code uses this plugin directly; `/init-video-workspace` scaffolds the equivalent setup into a `ProductVideos` Remotion workspace for **OpenAI Codex** too — see [Multi-tool support](#multi-tool-support-claude-code--openai-codex).

**Shape at a glance:** 5 agents · 1 user-invocable workflow with **5 internal phases + an optional Phase 0 (guided brief drafting) + 3 human gates** · 4 hooks (combined secrets-guard + media-size + render-quality-check + PII) · 13 skills (2 user-invocable + 3 conventions + 8 supporting) · 1 cross-tool `portable/` layer.

| Skill | Purpose | Entry Point |
|----------|---------|-------------|
| **init-video-workspace** | One-time setup — locate/clone/scaffold the ProductVideos Remotion workspace, verify ffmpeg/Node, guide `.env` setup, collect brand kit | `/platform-product-video-harness:init-video-workspace` |
| **generate** | Run the full 5-phase pipeline for one video project (+ V8/V9 vision QA inline before GATE #2) | `/platform-product-video-harness:generate <project-folder>` |
| **translate** | Localise a generated video to N languages (text + voice via ElevenLabs multilingual) | `/platform-product-video-harness:translate <project-folder> <iso-codes>` |
| **update-brand-kit** | Update colors / logo / tagline / fonts / personas / tone anytime after init | `/platform-product-video-harness:update-brand-kit` |

## Install

This plugin ships in the `harness-platform` marketplace on GitHub (`ameenaliu/harness-platform`), alongside the SDLC harness. Teammates who already have the marketplace registered only need to enable this plugin.

### Team-shared (recommended)

Commit a `.claude/settings.json` to your project repo (or your `ProductVideos` workspace) that auto-registers the marketplace and enables the plugin:

```json
{
  "extraKnownMarketplaces": {
    "harness-platform": {
      "source": { "source": "github", "repo": "ameenaliu/harness-platform" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "platform-sdlc-harness@harness-platform": true,
    "platform-product-video-harness@harness-platform": true
  }
}
```

Opening the repo prompts a one-time trust, after which the plugin is enabled automatically.

### Manual (one-off / testing)

```text
/plugin marketplace add ameenaliu/harness-platform
/plugin install platform-product-video-harness@harness-platform
```

## Quick Start

### 1. One-time setup

```text
/platform-product-video-harness:init-video-workspace
```

Walks through:

- Locating, cloning, or scaffolding the `ProductVideos` workspace (a local folder; you can clone from a GitHub repo you supply, or scaffold a new local folder and optionally `gh repo create` it later)
- Running `npm install` for Remotion
- Verifying `ffmpeg --version` and `node --version`
- Checking `.env` for `ELEVENLABS_API_KEY=…`; if missing, **guides you** to create or edit `.env` in your text editor (the plugin never auto-writes it)
- Collecting your brand kit (name pre-filled from the folder, palette, logo, personas, tone) into `brand/brand.json` and capturing voice config into `.claude/context/platform-video-context.md`
- Generating `.claude/settings.local.json` with pre-approved permissions

### 2. Per-video — set up a project folder

Inside your `ProductVideos` workspace:

```bash
mkdir projects/2026-05-25_inventory-launch
```

Drop in:

| File | Required? | What it is |
|---|---|---|
| `assets/` | ✅ yes (≥1 file) | PNG / JPG / SVG / MP4 assets from design exports or screen captures. |
| `brief.md` | optional | One paragraph describing what the video should communicate. **If absent, Phase 0 walks you through 4 questions and drafts it for you.** |
| `sample.mp4` | optional | A reference video the analyzer studies for pacing / shot composition / palette. |

### 3. Generate

```text
/platform-product-video-harness:generate projects/2026-05-25_inventory-launch
```

If `brief.md` doesn't exist, **Phase 0** kicks in first: a short Q&A (audience / tone / CTA / goal / optional notes) drafts it for you, you confirm, and the workflow continues. If `brief.md` already exists, Phase 0 is skipped.

After Phase 0, the workflow walks the 5 phases with 3 human approval gates. Final output: 3 MP4s in `projects/2026-05-25_inventory-launch/out/`:
- `9-16.mp4` (Reels, TikTok, YouTube Shorts)
- `1-1.mp4` (Instagram Feed)
- `16-9.mp4` (YouTube long-form, LinkedIn)

Posting is manual — open each platform's app or web uploader.

## Multi-tool support (Claude Code · OpenAI Codex)

`/init-video-workspace` scaffolds the cross-tool layer into the ProductVideos workspace. The role/workflow content is authored **once** in `portable/roles/` and `portable/workflow/`; each tool gets a thin wrapper:

| Concept | Claude Code | OpenAI Codex |
|---|---|---|
| Agents | plugin `agents/platform-video-*.md` | `.codex/agents/*.toml` (scaffolded) |
| Orchestration | Agent tool, single pipeline | `platform-video-generate` skill spawns subagents per phase |
| 3 internal gates | inline `AskUserQuestion` pauses for `APPROVED` | skill stops between phases for `APPROVED` |
| Conventions | plugin skills | `.agents/skills/{remotion,brand-kit,social-platform-specs}-conventions/` (scaffolded) |
| Baseline | plugin `CLAUDE.md` + scaffolded `AGENTS.md` | `AGENTS.md` (scaffolded) |
| Data policy | runtime hooks (4 guards) | scaffolded `AGENTS.md` + `portable/guards/` optional pre-commit / CI scan |

## The 5 Agents

| Agent | Phase | Does | Cannot |
|-------|-------|------|--------|
| **analyzer** | 1 | Extracts frames via ffmpeg, Claude vision reads each, outputs JSON outline (scene count, pacing, palette, suggested template) | Touch remote git / network beyond local tooling |
| **scriptwriter** | 2 | Picks closest template from `skills/script-templates/`, fills variables from brief + analysis, drafts script with voiceover + captions + scene timings | Run `Bash`; touch composition code |
| **compositor** | 3 | Generates `compositions/<slug>.tsx` + uses `_components/`, runs `npx remotion render` to produce 3 silent previews | Touch remote git / network; write outside ProductVideos workspace |
| **narrator** | 4 | Loads `.env`, calls ElevenLabs TTS + Sound Effects via curl, ffmpeg muxes audio + video into final MP4s | Edit `.env` directly (hook-blocked); edit source code |
| **reviewer** | 5 | ffprobes each output for aspect ratio + duration + audio levels; verifies brand colors used; halts on violation | Write or edit any file (read-only) |

Shared rules: `agents/shared/video-production-principles.md` (loaded by compositor + reviewer).

## The Phases (1 workflow, 3 internal gates, + optional Phase 0)

```
P0 (if brief.md missing)
Brief Q&A   →   P1          P2          P3          P4         P5
(orch)          Analyze →   Script  →   Build   →   Narrate →  Review
                (silent)    GATE #1     GATE #2                GATE #3
```

| # | Phase | What happens |
|---|-------|--------------|
| 0 | **Brief (if `brief.md` missing)** | Orchestrator hosts a short Q&A inline (audience / tone / CTA / goal / optional notes), writes `brief.md`, asks you to confirm. Skipped if `brief.md` already exists. No numbered gate — Step 6's `LOOKS GOOD` IS the checkpoint. |
| 1 | **Analyze** | analyzer agent extracts 1fps frames from `sample.mp4` (if present), reads each via Claude vision, writes `_cache/analysis.json` with scene count / pacing / palette / suggested template. Silent — no human gate. Cached so re-runs skip this if `_cache/` exists. |
| 2 | **Script** | scriptwriter picks closest template, fills variables from `brief.md` + `analysis.json`, drafts `script.md` (committed). **GATE #1** — human edits inline + replies `APPROVED` (or `NEEDS CHANGES <notes>` → re-draft). |
| 3 | **Build** | compositor generates `compositions/<slug>.tsx`, wires asset references via `staticFile()`, runs `npx remotion render` 3× (9:16, 1:1, 16:9) into `_preview/`. **GATE #2** — human reviews previews + replies `APPROVED` (or send back to Phase 2/3 with notes). |
| 4 | **Narrate** | narrator loads `.env` (halts with remediation if `ELEVENLABS_API_KEY` missing), calls ElevenLabs TTS per scene + Sound Effects for one ambient bed, ffmpeg muxes audio + video into 3 final MP4s in `out/`. |
| 5 | **Review** | reviewer ffprobes each output — aspect ratio matches target, duration within ±2s of script target, audio integrated loudness within ±2 LU of -16 LUFS (voiceover) / -28 LUFS (BGM), no clipped frames, file size within platform caps. **GATE #3** — human approves. |

**Nothing proceeds past a gate without explicit `APPROVED`.**

## Single-Workflow Pipeline

Unlike the SDLC harness's 4 workflows (discovery / backlog / dev / pr-review), video generation is a single-sitting, single-actor task with sequential dependencies — splitting into multiple user-invocable commands would just create cognitive overhead. The 5 phases (+ optional Phase 0) run inside one `/generate` invocation with inline gates.

## Key Concepts

### `.env` setup (the "harness guides you" pattern)

The plugin **never auto-writes** `.env` — the `secrets-guard.sh` hook actively blocks it. Instead, both `/init-video-workspace` and the runtime `narrator` agent check for the key and, if missing, halt with this exact remediation block:

```
⚠ ElevenLabs API key not found.

1. Get your API key at https://elevenlabs.io/app/settings/api-keys
   (Starter tier $5/mo required for commercial use — posting to social media counts.)
2. Create or edit <ProductVideos>/.env in your text editor
   and add this line:
     ELEVENLABS_API_KEY=sk_your_key_here
3. Re-run /platform-product-video-harness:init-video-workspace
   (or /platform-product-video-harness:generate <project>)

Your .env is gitignored and the secrets-guard hook will refuse any attempt
to commit it. The harness will never auto-write your .env — you stay in control.
```

At runtime the narrator loads the key with:
```bash
set -a; . "<ProductVideos>/.env"; set +a
```
The key stays in the subshell env — never in Claude's prompt context, never in any committed file, never on the Bash command line as a literal.

### Brand kit

Single source of truth in `<ProductVideos>/brand/brand.json`:

```json
{
  "name": "Your Brand",
  "tagline": "Your tagline here.",
  "colors": {
    "primary": "#2563EB",
    "primaryAlt": "#60A5FA",
    "accent": "#F59E0B",
    "ink": "#0B1020",
    "paper": "#F8FAFC"
  },
  "fonts": { "heading": "Inter", "body": "Inter" },
  "logo": { "path": "brand/logo.svg", "minSizePx": 56, "safeAreaPx": 32 },
  "lowerThird": { "barHeightPx": 96, "barOpacity": 0.85 }
}
```

These are the neutral starter values `/init-video-workspace` ships; the init brand-collection flow and `/update-brand-kit` replace them with your brand's. `name` is derived from the workspace folder.

Compositor imports + uses these tokens exclusively. Reviewer flags any hardcoded hex as `CRITICAL`.

### Script templates (6 ship in v0.1.0)

`skills/script-templates/`:
- `problem-solution-cta` (12–25s) — hook the pain, show the fix, drive action
- `feature-demo` (20–45s) — single feature deep-dive with on-screen UI
- `before-after` (15–30s) — side-by-side comparison
- `testimonial-style` (15–30s) — quote-led, attribution overlay
- `app-walkthrough` (30–60s) — multi-screen tour
- `launch-announcement` (10–20s) — date, headline, CTA

Each is markdown with `{{variables}}` and a target duration. The scriptwriter picks one based on the analyzer's hint + the brief.

### Aspect-ratio rendering

Remotion compositions reference shared `<Scene>` components that adapt to the active `Composition`'s dimensions. `compositions/Root.tsx` registers three `<Composition>`s per project — one for each aspect ratio — and `npx remotion render --concurrency 3` produces all three in one pass (~3–5 min for a 30s video on a modern laptop).

### Worktree-free mode

Unlike the SDLC harness, this plugin doesn't use git worktrees — video rendering is heavy I/O and Node-bound, and serial execution is fine. All work happens on the current branch of the ProductVideos workspace. Use feature branches if you want to iterate on competing concepts.

## Hooks (4 total)

| Hook | Event | What it blocks / does |
|------|-------|---|
| `secrets-guard.sh` | PreToolUse Write/Edit + Bash | API-key patterns (ElevenLabs `sk_[a-f0-9]{40}`, Figma `figd_…`, R2 keys) in any content; direct Write/Edit on `.env`/`.env.*`/`.secret`/`.key`/`.pfx`/`.pem`; `git add` / `git commit` of any `.env*` file |
| `large-media-guard.sh` | PreToolUse Write + Bash on git | Files >10MB being written or staged |
| `render-quality-check.sh` | PreToolUse Bash on `git commit*` | `npx remotion lint` + 1-frame dry render. Skip if no `compositions/*.tsx` changed. |
| `pii-pattern-guard.sh` | UserPromptSubmit | PII patterns in prompts: large UUID clusters, emails, Nigerian BVN/NIN, IBAN/PAN, JWT, .env shapes |

All blocks log to `<ProductVideos>/.claude/logs/policy-violations.log`. All hooks gate on the `<ProductVideos>/.claude/context/platform-video-context.md` sentinel — they only fire inside an initialised video workspace, never interfere with unrelated Claude Code sessions.

## FAQ

**Why isn't `git push` pre-approved?** Same reason as the SDLC harness — pushing affects shared state, so it always prompts.

**Can I run just one phase?** The phases share state through files (analysis.json → script.md → composition.tsx → out/*.mp4), and Phase 1 is cached. To re-render with the same script: re-run `/generate` and approve through the gates quickly. To swap an asset and re-render: replace the file in `assets/` and re-run — Phase 1 + 2 stay cached because their inputs didn't change.

**What if I want to skip the sample video?** Omit `sample.mp4`. The analyzer skips Phase 1's vision pass and the scriptwriter defaults to template selection from the brief alone.

**Render is slow — why?** Remotion renders are CPU-bound. A 30s video at 1080p × 3 aspect ratios takes ~3–5 min on a modern laptop. Use `npx remotion render --concurrency 3` (set in `remotion.config.ts`) to parallelise.

**ElevenLabs Free tier won't work?** Correct — Free tier license forbids commercial use, and posting your branded content counts. Upgrade to Starter ($5/mo) at minimum. The plugin doesn't verify your tier; it's your responsibility before posting.

**What if my .env gets committed?** `secrets-guard.sh` rejects `git add .env*` and `git commit*` when `.env*` is staged, so this should be hard. If it happens anyway (e.g., the guard was disabled), rotate the ElevenLabs key immediately via their dashboard, then `git filter-repo` to scrub the file from history before pushing.

**Can I post directly from the plugin?** Not in v0.1.0. Output is 3 MP4 files in `out/` — open each platform's web uploader or mobile app manually. Buffer/Hootsuite API integration deferred to v0.2.0.

**Where does background music come from?** ElevenLabs Sound Effects API generates short ambient beds matched to the script's tone. No separate music library needed for v0.1.0. For dedicated tracks, hand-place a `.mp3` in `projects/<slug>/audio/bgm.mp3` and the narrator will use it instead of generating one.

**Can I clone a brand voice?** Not in v0.1.0 (requires ElevenLabs Creator tier, $22/mo). Defer to v0.2.0.

## Session Continuity

- **Session restart** — `_cache/analysis.json` + `script.md` survive; re-run `/generate` and it skips Phase 1 + can resume from Phase 3.
- **`git push` failure** — local outputs are intact; just retry.
